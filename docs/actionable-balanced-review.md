# Actionable balanced review

Balanced assesses actual effects and the active user request, including routine
supporting steps. A broad tool name, local DOM change, private artifact delivery
or generated-intention mismatch is not proof of danger or a restriction conflict.
Follow-up discussion does not revoke authorized implementation or validation.
This is not blanket approval of all actions labelled low risk.

The independent reviewer provides an action summary and concrete explanation.
A claimed restriction conflict quotes a cited original instruction and explains
the conflicting effect. Invalid replies use the existing bounded repair and
remain closed on failure. Stored older receipts remain readable.
Escalation and denial text describes the review instead of misattributing Judge
risk to the factual classifier. It separately names a retained configured
checkpoint or final-policy restriction; a favorable model explanation cannot
hide the effective policy outcome. Configured auto-mode uncertainty denial is
identified as policy, not a fabricated user refusal.

An `ask` vote with low/medium risk and model-derived outside-task or uncertain
target/scope corrections remains an escalation, not a manufactured refusal.
Restriction conflicts and critical risk retain denial precedence.
Configured controls, observed facts, human refusals, required checkpoints,
outcome caps and read-only limits retain
precedence. Independently reviewed routine work can still be approved.

Regression fixtures cover the Gmail availability probe, agent `tools_get`,
departure-city selector inspection, private README delivery, authorized local
validation, restriction quoting and configured denial precedence.
Mocked tests do not guarantee every future model judgment.
