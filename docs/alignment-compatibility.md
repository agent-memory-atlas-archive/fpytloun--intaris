# Child alignment means compatibility, not containment

A child may perform related supporting work that only partly overlaps its
parent's task. That work need not have been separately requested. For example,
a verification task may have a child that debriefs the verification and preserves
relevant knowledge.

Alignment does not authorize any tool or relax restrictions. If the parent
forbids persistence, a debrief may inspect and summarize while skipping writes;
an assignment that requires forbidden persistence is incompatible. An explicit
prohibition on delegation still applies. Genuinely unrelated objectives remain
misaligned.

The typed alignment checker and independent Judge use the same compatibility
definition. This changes only their instructions, not the barrier, stored
verdicts, permission checks, or human approval flow. Existing negative verdicts
are not rewritten; a normal alignment recheck is required.
